# The design papers: what is in force

Sixty-two files. Most are history and say so in their own header. These ten are the contracts the code implements today, one paragraph each, with the paper that states the contract and the code that keeps it. Status words are the estate's: BUILT (running, tested), PROVEN IN TEST WORLDS (running between test machines, not in production), DESIGNED (a paper, no code yet). If the code and this page disagree, the code is right and this page is the defect.

1. **One record, the only truth.** Every act is one appended line; nothing is edited, nothing is deleted; every current state is computed from the lines. Paper: design/27 (the fundamental rules), design/11 (the record's shapes). Code: src/kernel/store.py (the append-only store, the per-record hash chain), src/kernel/canonical.py (one canonical form for hashing). BUILT.

2. **One gate; every act a decision citing its rule; refusals recorded the same way.** No act reaches the record except through the gate, which writes the decision and the rule it cited, or the refusal and the rule it cited, as a row. Paper: design/12 (the operations catalogue), design/18 (the law book), design/41 (the check architecture). Code: src/kernel/gate.py, src/kernel/opdefs.py (the declared operations and parameter kinds), src/kernel/boot.py (the founding rows). BUILT.

3. **Every view computed; delete everything but the record and rebuild identically.** No stored status, role or index: each view is a computation over the rows, done on read. Paper: design/13 (views), design/25 VERSION 2 (the view tree). Code: src/kernel/views.py; the proof is tests/test_ep22.py `test_kill_every_derived_thing_replay_from_the_record_alone_reconstruct_identically` and tests/test_ep24b.py `test_the_index_is_rebuilt_identically_from_the_record`. BUILT.

4. **The rulebook as data, amended only through its own gate.** The rules are rows in the founding pack and the record; a rule changes by an act the gate decides under the rules in force, never by editing code. Paper: design/27, design/18, design/29 (amendment without a gap). Code: src/founding/founding-pack.json (the genesis), src/kernel/gate.py (the rule operations), src/kernel/boot.py. BUILT.

5. **Authority as positive grants; the deny set computed; revoke one row.** Nobody holds a permission by default; a grant is a row, what is denied is everything not granted, a revocation is one row and takes effect at the next act. Paper: design/31 (campaign 2, authority), design/35 (the two times of authority), design/43 (rule, user identity and permission). Code: src/kernel/authority.py, src/kernel/gate.py (the pairing of actor class and operation cell). BUILT.

6. **The chain, keys as rows, attestation at boot; real keys when the library is installed.** Each record names the hash of the one before it; every key is a row; the program measures its own code at start and refuses to run on a mismatch; with the vetted library installed signatures, key wrapping and sealed content are real cryptography, without it the keys are stand-ins and a real operation refuses rather than fakes. Paper: design/34 (the fingerprint), design/37 (campaign 4, proof). Code: src/kernel/store.py (the chain), src/kernel/keys.py, src/kernel/crypto.py (the one import of the library), src/kernel/signer.py, src/kernel/vault.py, src/kernel/attestation.py. BUILT; the real-key state is BUILT and off by default.

7. **No delete: custody conserved, handover with a receipt.** Content never disappears; it changes hands, and the only removal is a handover whose signed receipt verifies before a byte leaves. Paper: design/46 (custody conservation), design/29 (tier conservation). Code: src/kernel/erasure.py (the handover ceremony), src/kernel/blobs.py (content by digest), src/bridge/custody.py. BUILT.

8. **The border: an outside submission is a draft the gate decides; identity at the tunnel; one row, one receipt, two bodies.** An outside process speaks as an entity; its request is a draft decided against the record like any act; an allowed draft yields a reply with a crossing id and a seal, a refused one a refusal through the system's own window. Paper: design/51 (campaign 5, networking), design/44 (its seed), design/39 (the program as entity). Code: src/kernel/border.py, src/subsystems/sockets.py, src/kernel/push.py (delivery to channels). BUILT; the two-body exchange PROVEN IN TEST WORLDS between a host and a guest.

9. **The glass box: two watched openings; nothing proposed executes.** Every program lives in its own box with exactly two watched openings, in and out; what a program proposes is a row the gate decides, never a thing that runs by being proposed. Paper: design/39 §3 (the two-channel glass box), design/52 (campaign 6, self-orchestrated institutions). Code: src/kernel/border.py (the openings), src/kernel/gate.py (the decision), src/kernel/obligations.py. The openings BUILT; the box's own contents empty until a program is hosted, which campaign 7 (design/54) builds.

10. **Recovery: the chain adjudicates, never truncation.** A damaged tail is judged by the chain against a named anchor; the rows past the break stay in the file as adjudicated history and a recovery row states the verdict; nothing is cut off. Paper: design/15 (the failure book), design/46. Code: src/kernel/erasure.py (`register_recover`, the recover ceremony). BUILT, with one known gap in the loader for a half-written last line, repair planned (planning/exec/EP-MAINT-OUTSIDE-6).

**What reconstruction promises.** Given the record alone, the program rebuilds the whole governing state, every actor, rule, grant, view and decision, identically; it does not promise a process's memory, a checkpoint, or execution state, and it rebuilds application content only insofar as that content was written as rows or named by digest in them.

**Which kernel route is active.** The active route is our own kernel written from a blank page beneath the seam (design/47 the seed, design/54 campaign 7, building since 2026-09-11; that paper arrives with the next public copy): the machine boots into our core, which performs exactly the twelve kinds of work the seam declares, and everything above the seam is unchanged. Design/16's route, replacing a Linux kernel subsystem by subsystem, is history and its header says so.
