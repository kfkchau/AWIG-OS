# GOV-OS — design 58: THE ROOT AGAINST THE BUILD (SCOT and the OGS core, primitive by primitive, against gov-os as built)

**Sources read whole this turn (reference/corpus, read-only): 01_SCOT_foundational_ontology/core-ontology.md (DRAFT 0.4, sixteen modules), scot_rationale.md (DRAFT 0.1), 02_OGS_governance_stack_unsorted/01_ontology/ogs-ontology-core.md and ogs-ontology-analysis.md. The build read against them: the founding pack (232 rows: 94 CREATE-OP, 73 CREATE-RULE, 42 CREATE-VIEW, 14 CREATE-INFO, 2 CREATE-ACTOR, 2 DECLARE-IO-WINDOW, 2 DECLARE-INTAKE, FOUND-STORE, CREATE-TUNNEL, GRANT), the row shape (actor, action, object, payload, rule_cited), the views, the gate. Status words: BUILT (rows and code, tested), PARTIAL (the primitive is present but a named part of it is not), ABSENT (nothing in the record or the code stands for it). The owner alone grades the reading; the code pointers are for anyone to re-drive.**

## 1 — The root, extracted (the primitives, in derivation order, each in one line)

    R0   REALITY                 the undistinguished substrate; nothing in it is same or different until observed
    R1   ENTITY vs RESOURCE      a thing that can originate change in itself vs one that cannot; a gradient, collectives are entities of entities
    R2   OBSERVATION             the act by which an entity turns reality bits into information; the first activity
    R3   SAME / DIFFERENT        the first output of observation; a property of the observation, never of the thing
    R4   INFORMATION             what observation produces; always shaped by the observer's model
    R5   CHANGE / UNCHANGED      same or different observed across time
    R6   THE FEEDBACK LOOP       information reshapes the observer; entities diverge on their own; sameness must be imposed
    R7   ACTIVITY                an entity producing change in an object (a resource or another entity); the observable, attributable unit
    R8   STRUCTURALITY           how far reality bits are designed to yield the same information across observers: unstructured → structured → fully structured (code)
    R9   REASONING               an entity changing information; output = f(input, model); model diversity is the deep source of difference
    R10  DECISION                the transformation that stops the change: the output fixed until new reasoning replaces it
    R11  RULE                    a decision that holds an expected activity unchanged across actors and time; RULES ARE INFORMATION, not reasoning — the user receives the expectation, never the why
    R12  COMPARISON              same-or-different between requirement (what should) and event (what did); itself an observation, a reasoning, a decision — so itself governable
    R13  GOVERNANCE              the management of rules (create, revise, retire, communicate, enforce) to produce sameness; it has a metabolism; lag is governance debt
    R13m META-RULES              governance's own acts are activities, so they need rules about rules; without them it governs by judgement
    R14  DIFFERENCE ENABLEMENT   the other technology: retain variation, make it visible, force interaction, constrain size, protect model diversity; lag is sterility debt
    R15  MUTUAL DEPENDENCY       every governance stage needs difference feeding it; difference needs minimal rules to interact
    O1   THE TRIAD               requirement (should), event (did), capacity (is — DERIVED from the events, never recorded directly); governance lives in the gaps
    O2   EVERY STAGE A DECISION  monitoring, analysing, reporting, announcing, communicating, enforcing — each an information transformation, so each a decision, so each governable
    O3   RULES FOR RULE-ADMIN    every governance stage has its own requirements, events and capacity, or the system governs by vibe
    O4   THE OPEN PIECE (OGS)    the derivation rules for capacity — which events count, over what window, under what conditions

## 2 — The build, primitive by primitive

    R0   REALITY              BUILT as the empty record before the founding: FOUND-STORE is the first row; nothing is distinguished before it. The founding pack IS the first observation of the world (design/27; src/kernel/boot.py).
    R1   ENTITY / RESOURCE    BUILT as the row's actor and object: an actor is an account row with a declared actor_class (human, ai, program — views.py:974/1573/1574, the three bands of the gradient), a resource is content by digest or a dictionary term (DICT-LAW: action/resource/actor as reusable dictionary records). PARTIAL: the gradient is displayed as three bands and a collective actor (an organisation as an entity of entities) is not yet a row — campaign eight's dimension (2) (design/56 B5).
    R2   OBSERVATION          BUILT as the act row itself and as SYS-RECORD ("SYSTEM may record any activity as evidence; recording is not permission to perform"): every act is observed into a row before it is anything else; the crossing trail on the body is the same at the metal (design/54 L18).
    R3   SAME / DIFFERENT     BUILT as the gate's decision and as the hash: a row's canonical hash is the machine's "same" (canonical.py); the gate's verdict is "same as what the rule expects" or "different, refused by name"; COMPARISON-LAW founds the owner's lens rule verbatim ("verdicts from different frames are different information — never a conflict, both kept").
    R4   INFORMATION          BUILT as the row: every row carries its observer (actor) and its frame (rule_cited); no row is observer-free. The founding pack's 14 CREATE-INFO rows are information rows by that name.
    R5   CHANGE / UNCHANGED   BUILT as append-only: change is a new row, unchanged is no row; "as_of" on every view (views.py fold(as_of)) is the observation at a moment; delete-and-regenerate tests are sameness across time (tests/test_ep22, test_ep24b).
    R6   THE FEEDBACK LOOP    PARTIAL: the loop where information reshapes the ACTOR's model is not modelled (no row says an actor's model changed); what is built is the loop where information reshapes the RULES — a rule row changes a later verdict (active_rules is latest-wins per rule_id, tier-protected, views.py:321-339) and TWO-TIMES-OVERTURN computes which recorded acts a later law reaches without rewriting anything. The entity-side loop is what the ai class and the cell law bound from outside rather than model.
    R7   ACTIVITY             BUILT as the row shape exactly: actor, action, object, payload, rule_cited — an entity producing change in an object, attributable, with the rule it stands on; the twelve ACT-KIND rules found the kinds of work the core performs.
    R8   STRUCTURALITY        BUILT as the cell law: every task in exactly one cell — S, U, U{s}, S{u} (views.py:1741 CELL_SET; CELL-LAW rule; gate.py:798 the pairing enforced at the write chokepoint); the actor's class band must carry the cell's arm. Campaign eight moves the S/U judgement onto the operation-on-its-object (design/56 B4), which is the root's "structurality is of the reality bits, not the thing". The fully-structured pole (executable code) is the enclosed program with a sealed rule set (design/56 B1/B2).
    R9   REASONING            PARTIAL: reasoning as "output = f(input, model)" is not a row; the build takes reasoning's OUTPUT as the act and governs that (the cell law's U cells are where reasoning lives, and an actor whose class lacks the U arm is refused). NLP as U is the campaign-eight precision. Model diversity as a governed property: ABSENT (see R14).
    R10  DECISION             BUILT: a row is a decision fixed; reversal is only a new row (no delete, ever — custody conservation, design/46; erasure.py's handover ceremony); the gate's own verdicts are rows (decision rows and refusal rows, the AR-2 form), so the deciding is itself recorded.
    R11  RULE                 BUILT: 73 CREATE-RULE rows, each rule_id + text + scope + enforced_by/enforcement (+ when/then for the 20 executable ones, + tier for the constitutional five); a rule is information a user receives — a refusal cites rule_id and never the reasoning; rules are amended through their own gate (design/29); CONST-SELF-PROTECT founds the tier that refuses its own amendment. PARTIAL on one field: NO founding rule row carries a rationale field (driven: zero rows with rationale/why/reason in payload) — the "reasoning that produced the rule lives in the lifecycle" (OGS) has no row; see §3.
    R12  COMPARISON           BUILT as the gate: requirement (active_rules, the cited rule's when/then) against event (the draft act) yielding same (a decision row) or different (a refusal row by name); the comparison is itself an act with a rule (the gate's own steps cite BOOT-INT / CAP-IS-LAW), so the self-referential property holds in the record.
    R13  GOVERNANCE           PARTIAL: CREATE-RULE and the latest-wins fold give create and revise; RETIRE-OP exists for operations (opdefs.py:3172-3280) but there is NO RETIRE-RULE act — a rule leaves force only by a later row with the same rule_id (revision), never by an explicit retirement row; communicate and enforce are built (announce = the row is visible by SIGHT-IS-LAW; enforce = the gate); the METABOLISM (how fast rules update; governance debt as a measurable) has no view.
    R13m META-RULES           BUILT: the constitution's five rows (CONST-*), VOCAB-DOOR-LAW, DICT-LAW, PACK-SCOPE, the two-times laws, CAP-IS-LAW (the founding runtime's own acts cite it 94 times) are rules about rule-making, and the gate's own acts are governed by them; the founding pack founds its own amendment path.
    R14  DIFFERENCE ENABLEMENT ABSENT in the record: no row retains variation, makes a divergent verdict visible, forces interaction, constrains size or protects model diversity. What exists is COMPARISON-LAW (two frames' verdicts both kept, never merged — the seed of "retain variation, make it visible") and the estate's seat law (a second reader on every plan, the owner's diversity-of-perspective principle) which lives in method documents, not rows.
    R15  MUTUAL DEPENDENCY    ABSENT as a row; present as practice (the plan author, the architect and the manager are three models on every unit).
    O1   THE TRIAD            BUILT and it is the whole design: requirement = rule rows, event = act rows, capacity = computed views (42 CREATE-VIEW rows, the view tree of design/25 v2; nothing stored, everything folded — views.py fold/view_fold/cached with as_of). The OGS "capacity is derived, never recorded" is gov-os's no-stored-state law.
    O2   EVERY STAGE A DECISION BUILT: every act crosses the gate, including the gate's (the founding runtime is an actor, PC_RUNTIME, 231 of 232 founding rows are its acts under a cited rule); campaign eight's load act makes even a program's start a decision row.
    O3   RULES FOR RULE-ADMIN BUILT for the acts that exist (CREATE-RULE/CREATE-OP/CREATE-VIEW each under a rule), ABSENT for the stages that are not acts: monitoring, analysing, reporting have no rows (the estate does them in planning/ and on the board, outside the record).
    O4   THE OPEN PIECE       BUILT: the derivation rules for capacity are exactly the view definitions and derivations (CREATE-VIEW rows with derivation; views.view_definitions / view_derivations / execute_view) and the load act's sealed rule set (design/56 B2) — the grammar the OGS analysis said still had to grow is rows.

## 3 — What the reading says is missing, in order of how much of the root it carries

1. **A rule's rationale as information (R11, OGS "rules are information; the reasoning lives in the lifecycle").** Today a rule row has text, scope, enforcement, when/then — and no row anywhere carries WHY the rule was made. The root says the why is information too, produced by reasoning in the lifecycle, and that it must be recorded even though the rule user never needs it. The row is small: a rationale (or the row it cites — an analysis row) on CREATE-RULE. Cost if absent: rule retirement and revision have no recorded ground, so the metabolism cannot be judged.
2. **Rule retirement as its own act (R13).** Operations retire (RETIRE-OP); rules only get overwritten by a later row of the same id. A retire row is the root's "retire" stage made visible, and it is what governance debt would be measured against.
3. **The lifecycle stages that are not acts today (O3): monitoring, analysing, reporting, announcing, communicating.** In this estate those happen on the board and in planning documents. The root says each is a decision and governable; the minimal form is a row per stage citing the rule it serves (a monitor row, an analysis row, a report row), so that "the reasoning behind the rule" (item 1) has somewhere to live.
4. **Governance metabolism as a view (R13).** With items 1–3 as rows, the rate of create/revise/retire and the lag between an event class and the rule that answers it are computable; without them there is nothing to fold.
5. **The collective actor (R1) and the entity-side feedback loop (R6, R9).** Campaign eight's dimensions (2) and (3) give the first; the second (an actor's model changing) is not a governance row in the root either — it is what the ai class and the cell law bound from outside, and that is a defensible stance, stated as such.
6. **Difference enablement (R14, R15).** The other half of the coin has no row. The seed is COMPARISON-LAW (keep both verdicts, never merge). The root's own operations — retain variation, make it visible, force interaction, constrain size, protect model diversity — would be the rows of a difference campaign; whether that is campaign eight's or a later one's is the owner's.

## 4 — The reading in one line

gov-os is the sameness half of the coin built to the root: the triad is its whole design, every act is a decision row citing a rule, rules are information amended through their own gate, and the derivation grammar the OGS analysis called the open piece is the view tree. What the root has that the record does not are the lifecycle's reasoning rows (why a rule, when it retires, what was monitored and analysed) and the entire difference half.

## 6 — Addendum, the same day, CORRECTED BY THE OWNER: OMGS coverage for a policy team using gov-os

**The first draft of this section (kept below as struck history) scored OMGS's lifecycle stages as row TYPES gov-os would have to found — a monitoring act, an analysis row, a report object, a communication row, a retire act — and marked most of them ABSENT. The owner corrected it in the same hour: with several users in one gov-os world, a submission is information sent between actors; monitoring is the record itself with the views computing every current state, continuously and better than any periodic review; analysis is users writing and revising their own information rows. That is the estate's own first principle (minimal primitives; record what happened, compute everything else) applied to OMGS, and the first draft broke it by importing OMGS's stage vocabulary as a schema — the nearest-template error. The stage names are ROLES that generic rows play, computed after the fact, never types the kernel must know.**

The corrected reading, stage by stage, with the generic row that plays the role:

    ECOSYSTEM (Doc 1)
    rule user / rule maker / decision maker    actors with grants and roles (GRANT rows, the roles view); a world names them as it likes
    rule resource                              content by digest, dictionary terms, devices, files
    rule environment vs ecosystem              one record; the boundary is a computed view over spaces and grants, not a founded row
    external factor / external activity        the border: an outside submission is a draft the gate decides; a peer fact is an INPUT-class row
    rule submission                            an information row sent from one actor to another (CREATE-INFO / the channel acts), or the draft of the CREATE-RULE act itself; "pending" is a computed view (sent, not yet decided)
    rule content                               the CREATE-RULE payload; the three OMGS content items the founding rows do not carry (targeted activities, intended outcome, review triggers) are payload fields a world declares once by amending the op (one AMEND-OP row under the meta-rules), not a kernel change
    meta-rule                                  constitutional-tier rule rows (CONST-*)

    LIFECYCLE (Doc 2)
    1 environment change                       the record: every environment activity is a row, change is a new row
    2 monitoring                               the record plus the views: every current state computed at any moment, continuous by construction; a comparison of an environment against a rule's assumptions is a VIEW (CREATE-VIEW row), never a monitoring act
    3 analysis                                 actors writing and revising information rows (their reasoning as content, attributable, timed)
    4 reporting (submissions)                  an information row addressed to the deciding actor; its arrival and its pendency are views
    5 decision                                 the CREATE-RULE act by an actor holding the grant, decided by the gate under the constitution; decision and refusal rows are the decision records
    6 announcement                             by construction: a rule exists only as a visible row (SIGHT-IS-LAW); when it binds is the two-times laws
    7 communication                            information rows (guidance, examples) sent to rule users, or a view that renders a rule for its users
    8 enforcement                              before the act: the gate's refusal by name; after the act: obligations rows and any act the world founds as a sanction or remediation, all generic acts under rules
    retirement / suspension                    a later row of the same rule_id whose then is empty or whose scope is closed (latest-wins), or a rule about that rule; a computed "in force" view
    the loop 8 → 2                             refusals and obligations are rows; a view over them IS the monitoring of enforcement

    ROLES (Doc 12)
    announcement before effectiveness          the two-times laws
    communication before negative enforcement  a rule that requires a communication row to precede a sanction act — one rule row, if a world wants it
    evidence-based enforcement                 every refusal cites its rule and its draft; every act is attributable
    consultation, feedback, discontent         information rows from rule users to rule makers; their existence and their answers are views
    accountability                             every act attributable by construction

The one sentence, corrected: gov-os covers OMGS's ecosystem and lifecycle as founded, because every stage is an act between actors or a view over the record, and the only thing a policy team has to add is its own rule content fields (targets, outcome, review triggers) by one op amendment. What stays outside gov-os is unchanged from §3: the difference half of the coin.

*Struck history — the first draft's table, kept so the correction is visible and not smoothed over:* the first draft marked analysis, reporting, communication, retirement and consultation ABSENT and monitoring PARTIAL "because no monitoring act row exists"; the correction above replaces each of those with the generic row that plays the role. The mistake was the architect's alone.

## 7 — Addendum, 2026-09-15: the CGL component grammars against the build (all nine modules and the README read whole)

Scored the owner's way (§6): a grammar is met when its distinction is either a computed view over rows, or a declared field on a term or a rule that one row can add; a stored tag on a verb or a resource is not the answer here (the estate retired stored rel_kind by ruling 7 for exactly this reason: the frame is computed, never stored).

    ACTIVITY (act01, directional)            INCORPORATED: the row shape actor / action / object / payload / rule_cited is the activity grammar.
    GEOMETRY (Venn2, five relations)         INCORPORATED: CREATE-RELATIONSHIP rows carry {subject, object, geometry, zone} (views.py:1092-1099); the containment geometries drive the actor tree and item tree (views.py:611-619, authority.CONTAINMENT_GEOMETRIES); the v2 parametric edge zone is the design of record (design/25 v2).
    MEASUREMENT (length / width / height)    PARTIAL: `measurement` is a founded parameter KIND (opdefs.py:229 PARAM_KIND_SET: quantity, text, bytes, measurement), so an act can carry a measured value the door types; the three axes are not a founded schema. Length is computable from the record (every row is timed: duration, delay, frequency are views); width is computable (how many actors or objects an act or a rule reaches: a count over rows); height (effect) is the one that needs a declared field or a rule's own scale. One row (the measurement kind's declared shape) makes the axes explicit.
    ACTION (move × transform)                COMPUTABLE, NO VIEW YET: an act MOVED its object when a containment or custody row changed for that object (the relationship rows, the custody handover), and TRANSFORMED it when the object's digest changed (content by digest); both read off the record after the act, never tagged on the verb. NA falls out (neither row moved). A view of two lines; no founding. This is stronger than the grammar's own form: the tag is observed, not asserted.
    RESOURCE (consumable × physical)         SPLIT: consumability is COMPUTABLE (a resource consumed is one whose later availability the record shows gone — the custody and erasure rows; a non-consumable is used and still present); physicality is DECLARED (a dictionary term field under DICT-LAW: physical or virtual is a fact about the thing the record cannot observe on its own). One field on the resource term; one view for consumability.
    COMPOSITION (whole / component; surface / inside; wireframe / content)   PARTIAL: whole and component are COMPUTABLE from containment rows (a component is a nested or embedded relationship of the part to the whole — Venn2 already carries it); surface, inside, wireframe and content are DECLARED distinctions about a thing's structure the record cannot observe, so they are dictionary-term fields or relationship zones (the v2 edge zone IS surface-versus-inside for a containment: nested = touching the edge, embedded = within the core). So: two of the three pairs ride Venn2 v2 as it stands; wireframe / content needs a declared field.
    ENFORCEMENT (scope, mechanism, source, strength)   PARTIAL, THE MOST BUILT OF THE REST: scope — the gate discriminates BLANKET from TARGETED rule blocks today (gate.py:624-641, _is_blanket_rule_block); mechanism — rule rows carry polarity (+ permits, - refuses: 20 founded rows), which is permit/refuse, not incentive/deterrent — an incentive is a rule whose then GRANTS, a deterrent one whose then REFUSES or OBLIGES, so the mechanism is computable from the rule's then; source — the rule's tier (constitutional) and enforcement (live at the gate = systemic; deferred = an obligation) cover systemic and discretion, while legal / policy / contract are a declared field on the rule (its provenance, one field); strength (E against C) — ABSENT, and it is a measurement-kind field on the rule's then; escalation — obligations rows chain (an obligation fires when its then-op is recorded with the ref and the promised params, re-armed on amendment: obligations.py:62-84), which is the grammar's enforcement-node sequence as rows.
    CONNECTION (1→N, AND/OR/XOR, FS/SS/FF/SF)   PARTIAL: rule rows carry when / then, so a rule is a condition→outcome link and an obligation is an activity→activity link (1→1 and 1→N as one rule with several then entries); the founded whens are mostly empty (always); conjunction is the list; OR / XOR / NAND / NOR are not a founded form (a second rule is OR; XOR and the negations need a declared operator in when); the temporal forms are COMPUTABLE from rows (finish-to-start is "the outcome row's time is after the trigger row's time"; start-to-start likewise) and are what the two-times laws already reason with for a law's own timing. One declared operator field on when; the timings are views.
    ARCHITECTURE (hierarchy / network / system)   COMPUTABLE, BY RULING: rel_kind is deliberately NOT stored (views.py:1096, ruling 7); hierarchy is the grant chain and containment (authority flows down a space tree), network is the border's peer facts and mutual grants, system is the record's own flow of rows; a view names the frame per relationship from those. No founding.

The one sentence: two grammars are the build's own shape (activity, geometry), five are computable from rows with a view apiece (action, resource consumability, composition whole/component, connection timing, architecture), and the remainder are declared fields a world adds by one row each (resource physicality, wireframe/content, enforcement source and strength, a connection operator, the measurement axes). Nothing in the nine needs a kernel change; the two that touch a rule's own shape (enforcement strength, connection operator) are op amendments under the meta-rules.
